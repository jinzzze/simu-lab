# 项目企划 v0.1

日期：2026-10-03。状态：开发前范围与实验设计。

项目名称：Hand–Object Supervision for Robot Learning（手与物体辅助监督的机器人学习）。

申请截止时间：2026-10-09 23:59 BST，以已读取的招聘页面为依据。计划在截止前完成公开仓库及申请材料；当前仅创建本地企划，没有发布或提交。

## 1. 项目目标

申请人用手机亲自拍摄桌面推物视频。在相同原始视频、模型初始化和机器人适配数据条件下，比较四种视觉训练方式：原始 RGB 基础训练、增加物体辅助监督、增加手部辅助监督、同时增加二者。

训练后的视觉模块接入同一个状态世界模型和规划控制系统，驱动仿真中的 Panda 机械臂把物体推入目标区域。

主要问题：显式结构化辅助监督是否改善最终任务成功率？

次要问题：物体与手部信息分别贡献多少；两者是否互补；改善是否来自更准确的感知；有限机器人视觉适配数据下是否更有价值？

这是受控的视觉表示消融研究。不能预先承诺成功率提升，也不将检测关键点本身声称为全新方法。

## 2. 锁定的范围

- 一个桌面推物任务，一个尺寸已知的刚性方块，已知桌面平面。
- 固定摄像机、缓慢短距离推送；初始版本无障碍物。
- 真实操作使用手持刚性推杆，完整记录手、推杆和物体；仿真尽量匹配推头几何。
- 真实视频逐帧提取视觉训练样本；v0.1 不宣称实现时序视频理解或生成式视频世界模型。
- 四组在真实视频阶段使用相同的 RGB；检测结果只作为辅助训练目标，不作为部署必需输入。
- 部署时的视觉物体状态来自模型预测；机器人自身状态和目标可以作为四组一致的输入。
- 后端世界模型、动作集合、规划参数及执行器在四组主比较中保持固定。
- 先实现 A、D 的开发闭环，正式实验必须补齐 A、B、C、D。

当前不并行增加 VLA 微调、强化学习、复杂抓取、多物体、多机器人或主动数据采集。这些属于主实验完成后的另行扩展。

## 3. 四组实验

| 标识 | 原始 RGB 基础训练 | 物体辅助损失 | 手部辅助损失 |
| --- | --- | --- | --- |
| A / rgb | 相同 | 关闭 | 关闭 |
| B / rgb_object | 相同 | 开启 | 关闭 |
| C / rgb_hand | 相同 | 关闭 | 开启 |
| D / rgb_object_hand | 相同 | 开启 | 开启 |

所有模型创建相同架构和辅助头，只改变辅助损失开关。对应训练种子的初始权重、批次顺序和增强随机数尽可能配对。

主要比较：D−A 的成功率差异。必要消融：D−B、D−C，同时报告 B−A 和 C−A。

解释限制：A 是“真实视频视觉预训练不使用额外物体/手部标签”的对照。所有组后续都会使用相同的仿真状态标签，且共享的世界模型本身也使用状态训练数据。不能将 A 描述成整个机器人系统完全未接触状态监督。

## 4. 技术架构

### 4.1 真实视频视觉预训练

初始视觉骨干拟采用相同 ImageNet 预训练权重的 ResNet-18；具体依赖版本在环境验证后锁定。

共同基础任务采用同一时刻图像的视觉特征一致性：保留一份冻结的初始编码器作为教师，学生编码器在经过增强的 RGB 上预测教师对原图的特征。教师固定且不使用本项目的物体、手部或任务标签。四组使用完全相同的教师与目标。

初始增强只使用适度光照、颜色和模糊变化。所有组均处理完整画面，不对 A 单独使用较弱的数据预处理，也不按物体标签给基础组生成裁剪。以后加入几何增强时，必须同步变换关键点、边框和有效性掩码。

训练目标：

`L = L_consistency + lambda_object * L_object + lambda_hand * L_hand`

- `L_object`：当前帧物体中心、边框等定位伪标签。朝向仅在测量足够可靠时加入。
- `L_hand`：当前帧的二维手部关键点，使用检测有效性和数据质量掩码。不得假设工具提供了并不存在的逐关键点置信度。
- A 的两个辅助权重为零；B、C 各开启一项；D 开启两项。
- B/D 使用相同物体损失权重，C/D 使用相同手部损失权重。权重和训练步数由开发验证流程确定，在测试前冻结。

手部检测器和物体检测器在四组实验期间固定。检测器使用的外部预训练权重属于额外先验，需在报告中说明；这项实验检验的是借助这些工具的辅助监督价值，而非“完全没有额外知识”。

### 4.2 统一的仿真视觉适配

四组都使用相同仿真图像及状态标签，训练同构状态估计头，输出当前物体的桌面位置和朝向。真实预训练结束后全部丢弃物体/手辅助头，按配对种子初始化新的相同状态估计头，仅迁移编码器。编码器是否全部微调及学习率策略，对四组保持一致并在测试前冻结。

主实验预算暂定为 30 条完整仿真推送轨迹；10、100 条为样本效率扩展。这里是视觉适配数据预算，不能将其误写为整个项目的全部仿真交互量。

真实手部辅助头不在 Panda 部署时调用，不要求机器人画面出现人手。

### 4.3 共享的状态世界模型

输入为当前物体/工具状态与事先定义的推送指令，输出一次推送后的物体位置和朝向变化。

使用自采真实交互及明确记录的仿真标定数据训练，在四组最终实验前冻结为同一个检查点。数据来源和全部标定交互单独计入项目预算。

这部分研究的是宏动作结果，不是手部关节到 Panda 关节的直接映射。先比较简单回归和小型 MLP，以验证集选择足够可靠的实现；不得为某一视觉组单独重训世界模型。

### 4.4 规划与执行

宏动作暂定：4 个接触侧 × 3 个接触偏移 × 2 个长度，共 24 种。高度、速度和推送方向规则固定，动作配方在真人采集前生成。

规划器从视觉估计状态出发，用共享模型枚举两步候选推送，按接近目标及动作代价选择方案。只执行第一步，重新观测后再规划。

低层执行器负责抬起、接近、下降、直推及退出，不能读取目标来暗中修改推送策略。接触点必须由当前估计物体位姿与动作配方计算，不能在 A/B/C/D 主实验中读取仿真真实物体位姿纠正执行。

仿真真实物体状态只用于训练标签、最终评分和独立 oracle 诊断。物理引擎正常进行碰撞和动力学计算，不属于向模型提供真值。

## 5. 数据计划与边界

### 5.1 真实采集

- 先完成约 12 次试采，确认视角、遮挡、标定、手部检测和机器人动作定义相容。
- 通过试采后，初始预算约 144 次独立推送，24 种配方各 6 次；数量在试采后依据覆盖情况冻结。
- 摄像头固定；每次记录初始场景、预定动作、实际轨迹和结果。
- 手关键点不是推杆接触点；额外记录推杆几何和末端位置，供标定、共同世界模型和诊断使用。它不偷偷成为某一视觉组的额外输入。
- 推不动、滑移和意外转动属于真实结果。只按事先定义的技术质量或执行容差规则剔除样本，并记录理由。
- 拍摄由申请人本人完成。合成数据只能用于接口与开发测试，不能冒充挑战要求的自采数据。

### 5.2 数据划分

先按采集批次/完整轨迹划分训练、验证、测试，再抽帧和派生伪标签。同一轨迹及其增强、裁剪、重编码版本不能跨集合。

同一批 RGB 和同一划分用于四组。检测失败时保留图像，用掩码忽略不可靠辅助项，不为某一组另选容易样本。

所有手工纠正必须留痕，并按统一规则作用于对应伪标签。最终测试标签不用于选择阈值、损失权重、检查点或控制参数。

### 5.3 计划的数据记录

每条记录至少包含：`episode_id`、`session_id`、数据来源、原始文件校验值、时间戳、预定动作 `a_cmd`、实际执行记录、初始/最终测量状态、拆分归属、质量标记、标签工具版本。

数据账本分别列出：真实视觉预训练数据、共享世界模型数据、仿真标定数据、仿真视觉适配数据、开发验证数据、最终评测轨迹。不得混淆不同阶段预算。

### 5.4 因果与坐标约束

当前决策只能使用当前及历史观测。完整视频的未来轨迹可作为训练目标或离线质检，不能作为当前输入。

动作采用事前指令，不能用动作结束后的实际位移替代部署时未知的控制量。

MediaPipe 的手部局部三维坐标不等于机器人基坐标。v0.1 手监督优先用二维坐标；涉及度量坐标时必须有独立标定。处理物体朝向误差时考虑周期性和物体对称性。

## 6. 评测协议

### 6.1 主要终点

主要终点为同一测试场景分布上的任务成功率差异 `D−A`。成功判据暂定最多 10 次推送、最终中心距目标不超过 2 cm，并在规定短暂稳定窗口内满足条件。任务难度、阈值和稳定窗口在开发集确认后冻结。

最终预算初定：每组 3 个训练种子，每个种子评测相同的 50 个场景，共 600 个主评测 episode。若性能测试表明预算不足，在查看正式测试结果前统一修订并记录；不得只给有利组追加运行。

报告每个种子的成功次数/总次数及组间配对差异，给出不确定性区间。重采样以完整 episode/场景为单位，并尊重训练种子分组，不将帧视作独立样本。

### 6.2 次要指标

- 物体位置误差和考虑对称性的朝向误差。
- 共享世界模型接收视觉估计后的动作结果预测误差。
- 最终目标距离、推送次数、超时、离开工作区及无进展比例。
- 完整 RGB→状态→规划→执行命令的每步耗时。
- 训练阶段物体/手部伪标签生成的额外时间与资源，和部署耗时分开报告。
- 手部遮挡、检测失败、偏心接触等子集上的误差，仅使用事先定义的分组规则。

### 6.3 诊断参照

单独运行准确状态输入的 oracle 版本，诊断控制后端和感知瓶颈；该版本不是严格数学上界，不混入四组主结果。

可保留无需项目视频预训练的视觉编码器参照，以及解析推送模型参照，但不替代必需的 A/B/C/D。

### 6.4 公平性

相同图像、分辨率、主干、初始化、基础训练目标、采样规则、增强、优化预算、仿真适配样本、动作菜单、控制代价和测试场景。仅改变定义好的辅助损失开关。

调参只使用开发验证数据，遵循共同规则。最终结果不挑种子、不只展示成功视频。若 D 没有优于 A，报告无提升或负作用及其证据。

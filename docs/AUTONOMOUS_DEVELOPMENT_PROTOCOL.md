## 研究与当前阶段

保留 A/B/C/D 的共同 RGB、模型初始化、基础特征一致性任务、独立物体/手部辅助损失、共同仿真适配数据和共同控制后端。当前任务仍是将 20×20×10 mm 方块抓起放到黑线右侧，定义见 CURRENT_TASK.md。

本轮先做**探索性开发实验**。12 条真实样片属于同一保守 scene-family development pool，实际 session 元数据未知；不随机拆帧，不将其中一部分伪称为未见场景的真实测试集。通过质检后可以把同一批样片用于全部四组的开发预训练，最终泛化证据需要独立场景/更多真实采集。

伪标签用 RGB 颜色、形状、尺寸和固定板参照生成可见黑色部分的框。它不是完整遮挡物体真值。手部标签来自固定 MediaPipe；二者的有效掩码独立，物体组不能读取手关键点。无法定位时保留 RGB、只屏蔽物体损失。2D 手/物体坐标不转换为三维人类动作。

## 抓取后端修订

第一版采用固定状态机：接近、下降、闭合、抬升、右移、下降释放、撤离。控制器接收视觉预测的初始桌面 XY、机器人自身状态及共同已知目标；执行中不读取真实物体位置纠偏。方块高度与初始朝向固定为已知任务参数。真值只进入标签、评分或单独 oracle 诊断。

**旧推杆世界模型与 MPC 不作为本轮完成项。** 用户将任务改为抓取后，需要重新定义相应动力学/动作模型；为先检验视觉辅助监督对实际抓取的影响，本轮使用四组完全相同的状态机后端。该架构变更不更改四组的主要比较变量，但当前交付只能称为抓取与视觉对照原型，不能宣称原始世界模型方案全部实现。

## 预先固定的开发评估原则

- 真实预训练使用同一个固定教师与温和颜色增强，同种子配对 batch/增强顺序；固定训练步数，不挑最好看的种子。
- 仿真适配：从明确独立的 scene seeds 生成 train/validation/test；按完整 scene 划分，变体不跨集合。
- 状态估计头重新初始化，只迁移编码器；仿真学习目标是初始桌面 XY。共同使用相同样本与优化步数。
- 先确认 oracle 抓取成功，再跑视觉模型。对新模型输出与共享后端的开发评测不等于最终预注册实验。
- 对所有 A/B/C/D 报告实际误差、成功次数/总数、训练预算和失败原因。零提升或负作用照实保留；未知字段保持未知。
- 输出中明确标出：synthetic unit tests、oracle diagnostics、pilot-development model runs、未完成正式评测。
